# assets/

随包分发的静态素材（模板、图标集、示例图片）。当前 v1.0 只带**示例素材**，不带图标库。

## 当前内容

| 文件 | 用途 | 来源 | 授权 |
|---|---|---|---|
| `examples/assets/warehouse.jpg`（1536×1024） | 端到端示例 `examples/demo.yaml` 的 s01 主图 | 本包内置示例，由图像模型生成（非实拍） | 随本包示例自由使用 |

生成图**不是事实证据**：它可以说明「这一页想让人看见什么」，不能用来证明数据、地点或人物。
在 brief 里写 `function: proof` 又没有真实来源时，判断层会提 `ASSET_PROOF_UNSOURCED` 追问。

## 命名与存放

- 素材跟随 brief 放在同一目录树内（路径相对 brief 所在目录解析），
  `guard` 对项目目录之外的文件只告警 `ASSET_OUTSIDE_PROJECT`，交付时需单独确认授权；
- 一个文件被多页共用时写在同一目录，不要在页面目录里复制副本（`asset_sha256` 会显示不一致）；
- 建议 `领域_主体_用途.jpg`（如 `retail_warehouse_hero.jpg`），便于审稿时对齐叙事。

## 引入外部素材时的最低要求

1. 来源可追溯（拍摄/购买/生成的记录），放在素材旁 `*.source.txt`；
2. 授权允许商用与再分发，且允许裁剪；
3. 有可辨识人物时确认肖像使用范围——本包不做人脸检测，靠人工核对；
4. 分辨率满足 `policy/strategy.yaml` 的 `assets.min_long_side_px` × `oversample`
   （放 496×624 的图位至少要 992×1248 的源图，不足会 `ASSET_RESOLUTION`）。

## 不做什么

- 不内置图库（避免风格趋同：一套素材会让十份稿子长得一样）；
- 不为「让页面好看」自动配图：出图必须由作者在 `brief` 里声明，并写出 `reason`；
- 像素度量在 `scripts/assets.py`（只给事实：尺寸、亮度、纹理、对比度、裁切损失），
  判断与拦截在 `judgment` / `guard`，不在这里。
