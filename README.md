# ppt-visual-art-director

**v6.0.0** — 让 AI 以视觉设计总监的方式做 PPT：新建稿把判断写成 brief、把设计写成 plan、确定性地落成原生可编辑 PPTX；既有稿先解析读懂，再定点编辑，保留原有内容、结构与格式。

它不做模板套用，也不从行业关键词推风格。工作方式是：读懂受众与证据 → 找一条洞察 → 定一个能约束全篇的概念（含它否决了什么）→ 定艺术指导 → 排叙事节奏 → 逐页构成 → 编译 → 看真实渲染 → 定点修正。面对既有稿则反过来：先 `inspect` 读出它是什么，再只改被点名的对象，其余一律不许动。

> 一句话原则：设计判断归你，确定性执行归脚本，审美与签收归人。机器检查不等于好看，预览不等于目标环境通过。

## 结构

```
SKILL.md                  八条判断、判断顺序、brief、任务路线、执行、验收、交付
references/
  design.md               概念与原创、艺术指导、叙事、空间、版式、信息设计、
                          排版、色彩、图像、诊断、复核维度
  build.md                plan 语义、坐标、叠放、文本与 runs、图表口径、素材、页码、
                          网格、命令、诊断码、改稿、机器边界
scripts/
  compile.py              plan.json → 原生可编辑 PPTX（校验 + 编译 + 整稿设计信号）
  verify.py               plan ↔ PPTX ↔ 真实渲染（对象核对、渲染核对、证据报告）
  revise.py               既有 PPTX 的定点编辑（改字／挪框／换图／改数／调层级／换底色）
  inspect_pptx.py         只读解析既有 PPTX（改稿与评审第一步）
  grid.py                 列数或比例 → 英寸坐标；三分线与黄金位
  plan.schema.json        数据契约（字段形状与类型条件）
  limits.json             技术阈值、默认值、字体别名
requirements.txt
```

## 安装

```bash
python -m venv .venv && . .venv/bin/activate      # Windows：.venv\Scripts\activate
pip install -r requirements.txt
```

Python 3.9+。脚本不联网。真实渲染核验另需 LibreOffice；缺失时 `verify.py` 会跳过渲染并说明哪些判断因此没有依据。

## 新建稿三步

```bash
python scripts/grid.py --span 1:6 --span 8:5      # 先算坐标（也可 --split 5,7 / --guides thirds）
python scripts/compile.py plan.json out.pptx      # 再编译（已有同名文件需 --force）
python scripts/verify.py plan.json out.pptx       # 最后核验（写 render/）
```

plan 的最小骨架见 `references/build.md`「最小骨架」。

## 改既有稿三步

```bash
python scripts/inspect_pptx.py 原稿.pptx           # 读出页数、母版、版式、对象、底色、宏
python scripts/revise.py 原稿.pptx edit.json out.pptx
python scripts/inspect_pptx.py out.pptx            # 核对结果，必要时再渲染看
```

`edit.json` 只描述要改什么，不描述整份稿。改完自动做保留核对：页数、母版、版式、主题字体、宏、逐页动画／切换／备注，以及**未被点名对象**的类型／几何／旋转／文字；**只改文字的操作还会比对第一段的字级**——原稿继承自版式的 44pt 标题不会被写成 18pt。任何漂移记 `E-PRESERVE` 阻断。原稿永远不会被覆盖。

## 能做什么

- **判断有落点**：`brief` 里写洞察、概念、**否决项**、艺术指导五参数与母题；`veto` 至少一条——否决不了任何东西的概念没有指导力。
- **原生可编辑**：文本（逐段逐 run 混排，`runs` 可跨段换色换字重）、图片（裁切、透明度、`duotone` 压进整稿色域）、形状（圆角半径、描边、旋转、渐变与半透明）、路径（折线、箭头、闭合多边形、锚点连接）、组合、表格、图表。旋转对以上所有类型一律生效。
- **图表**：柱（横／竖／堆叠／百分比）、线、面积（含堆叠）、饼、环、散点、柱＋线组合，直标分柱层／折线层／饼环三套规则，轴线与轴名可控。
- **既有稿定点编辑**：十种操作（改字／挪框／改样式／填色／描边／调层级／换图／改数／删对象／换底色），作用在声明的对象上。母版、版式、动画、切换、SmartArt、备注原样保留。
- **空间可算**：等分列、按比例切版心（`--split 5,7`）、三分线与黄金位（`--guides thirds|golden`）——先用比例定骨架，再落具体坐标。
- **整稿信号**：连续同构、标题下细线、无功能英文标签、素材复用、待主张页、满幅图开场——只指出位置，判断归人。
- **确定性**：叠放顺序、页码、几何、样式全部由 plan 决定；编译前阻断硬错误，不静默改设计。

## 五条硬事实

- **坐标单位是英寸**，原点在页面左上角；16:9 画布 13.333 × 7.5，4:3 是 10 × 7.5；字号单位是 pt。
- **编译器总是生成新文件**，不就地修改原稿；目标文件已存在时默认不动。
- **视觉质量只有在真实渲染且确实看过图像时才可能被判断**。缺任一条件，如实说未核验。
- **`duotone` 在 PowerPoint 生效，LibreOffice 只做去饱和**：渲染核验能证明结构与明暗，不能证明色相。
- **定点编辑有边界**：不新增页、不复制页、不改页序、不改系列数、不动母版与版式本身、不能加动画或切换；组内对象要先取消组合。

## v5 → v6

plan 契约没变：v5 写好的 plan 直接编译，`edit.json` 格式不变。改的是执行与文档。

- **修掉两个静默降级**：① 改稿的 `text` / `style` 操作会把继承字级写死（真实稿的 44pt 标题被改成 18pt，报告仍 READY）——现在只写已知属性，并新增"只改文字不得改样式"的 `E-PRESERVE` 闸；② `rotation` 只有文字/形状/组合生效，图片、路径、图表上声明了会被丢掉——现在在出口统一应用，核验对所有类型回读。
- **补齐核验空洞**：路径不再只数顶点，逐点比对坐标与闭合；两点连接符查端点位置；页码查是否在最上层；渲染里的页码旁不再用"是不是数字"放过越界文本。
- **去掉会误导的兜底**：素材解析不再"同名不同扩展名"乱猜（`hero.png` 与 `hero-2.jpg` 并存时曾会取错，且核验器同错）；空页给 `W-EMPTY`。
- **代码瘦身**：函数内重复导入归到模块级，直标的 XML 改写从五处收成一套顺序表，轴与字族的重复检查各收成一处。
- **文档重写**：SKILL 与 design 去重（概念、原创、机器边界各只讲一次），三张张力／版式装置表收成一张版式表加一段张力手段。
- **代价要说清**：四份文档 85,726 → 81,166 字节（−5.3%，`design.md` 37,544 → 33,802 是删表省下的）；代码 190,424 → 194,879 字节（+2.3%）——新增的顶点、旋转、页码层级核验比删掉的重复导入更多。这一版换的是正确性，不是行数。判断一条没删：逐字比对的跨文件重复只有三句，都是"摘要指向详述"。
- **回归**：负向用例 31 条，每条都是"先破坏、再确认它会响"——包括本轮修掉的四个缺陷（改字写死继承字级、图片／路径旋转丢失、折线顶点位移、连接符端点位移）。
