# ppt-visual-art-director

**v7.0.0** — 让 AI 以视觉设计总监的方式做 PPT：新建稿把判断写成 brief、把设计写成 plan、确定性地落成原生可编辑 PPTX；既有稿先解析读懂，再定点编辑，保留原有内容、结构与格式。

它不做模板套用，也不从行业关键词推风格。工作方式是：读懂受众与证据 → 找一条洞察 → 定一个能约束全篇的概念（含它否决了什么）→ 定艺术指导 → 排叙事节奏 → 逐页构成 → 编译 → 看真实渲染 → 定点修正。面对既有稿则反过来：先 `inspect` 读出它是什么，再只改被点名的对象，其余一律不许动。

> 一句话原则：设计判断归你，确定性执行归脚本，审美与签收归人。机器检查不等于好看，预览不等于目标环境通过。

## 结构

```
SKILL.md                  八条判断、判断顺序、brief、任务路线、执行、验收、交付
references/
  design.md               概念与原创、艺术指导、叙事、空间、版式、信息设计、
                          排版、色彩、图像、诊断、复核维度
  build.md                plan 语义、坐标、叠放、文本与 runs、图表口径、素材、页码、
                          网格、命令、诊断码、改稿、机器边界
scripts/
  compile.py              plan.json → 原生可编辑 PPTX（校验 + 编译 + 整稿设计信号）
  verify.py               plan ↔ PPTX ↔ 真实渲染（对象核对、渲染核对、结构核对、证据报告）
  revise.py               既有 PPTX 的定点编辑（改字／挪框／换图／改数／调层级／换底色）
  inspect_pptx.py         只读解析既有 PPTX（改稿与评审第一步，含部件级指纹）
  grid.py                 列数或比例 → 英寸坐标；三分线与黄金位
  plan.schema.json        数据契约（字段形状与类型条件）
  limits.json             技术阈值、默认值、字体别名
requirements.txt
```

## 安装

```bash
python -m venv .venv && . .venv/bin/activate      # Windows：.venv\Scripts\activate
pip install -r requirements.txt
```

Python 3.9+。脚本不联网。真实渲染核验另需 LibreOffice；缺失时 `verify.py` 会给出 `PARTIAL` 并说明哪些判断因此没有依据。

## 新建稿三步

```bash
python scripts/grid.py --span 1:6 --span 8:5      # 先算坐标（也可 --split 5,7 / --guides thirds）
python scripts/compile.py plan.json out.pptx      # 再编译（已有同名文件需 --force）
python scripts/verify.py plan.json out.pptx       # 最后核验（写 render/）
```

plan 的最小骨架见 `references/build.md`「最小骨架」。

## 改既有稿三步

```bash
python scripts/inspect_pptx.py 原稿.pptx           # 读出页数、母版、版式、对象、底色、宏
python scripts/revise.py 原稿.pptx edit.json out.pptx
python scripts/inspect_pptx.py out.pptx            # 核对结果，必要时再渲染看
```

`edit.json` 只描述要改什么，不描述整份稿。改完做**四层保留核对**：结构（页数／母版／版式／页序／宏）、逐页特性（只查被点名页的动画／切换／备注，其余页连这些部件都不许变）、对象（没点名的逐个比对几何／填充描边／图片字节与裁切／图表载荷）、包内部件（除被点名页的 `slideN.xml` 及其 rels、`[Content_Types].xml` 与新增的 `media/`、`embeddings/`，其余逐字节一致）。另有两条闸：**只改文字的操作，改动后每段用到的样式必须是它原来就有的**——允许少用，不许新出现（继承自版式的 44pt 标题不会被写成 18pt）；原段混排而新文字段数 run 数不同时记 `W-RUNS` 明说"已统一为该段首个 run 的样式"。任何漂移记 `E-PRESERVE` 阻断，**此时交付路径一个字节都不写**，证据另存 `<out 名>.preserve-failed.pptx`。原稿永远不会被覆盖。

## 能做什么

- **判断有落点**：`brief` 里写洞察、概念、**否决项**、艺术指导五参数与母题；`veto` 至少一条——否决不了任何东西的概念没有指导力。
- **原生可编辑**：文本（逐段逐 run 混排，`runs` 可跨段换色换字重）、图片（裁切、透明度、`duotone` 压进整稿色域）、形状（圆角半径、描边、旋转、渐变与半透明）、路径（折线、箭头、闭合多边形、锚点连接）、组合、表格、图表。旋转对以上所有类型一律生效，任意角度按 360 取模。
- **图表**：柱（横／竖／堆叠／百分比）、线、面积（含堆叠）、饼、环、散点、柱＋线组合，直标分柱层／折线层／饼环三套规则，轴线与轴名可控，截轴要留 `note`。
- **既有稿定点编辑**：十种操作（改字／挪框／改样式／填色／描边／调层级／换图／改数／删对象／换底色），作用在声明的对象上。母版、版式、动画、切换、SmartArt、备注原样保留。
- **空间可算**：等分列、按比例切版心（`--split 5,7`）、三分线与黄金位（`--guides thirds|golden`）——先用比例定骨架，再落具体坐标。
- **核验有证据**：对象逐项回读；渲染后把预期文字与**真实渲染出的文字逐块比对**（掉字、被替代字体挤掉都会响）；查行首标点与末行孤字、声明的角度是否真进渲染、原生图表与内嵌工作簿与 media 部件是否都在文件里。
- **整稿信号**：连续同构、标题下细线、无功能英文标签、素材复用、待主张页、满幅图开场——只指出位置，判断归人。
- **确定性**：叠放顺序、页码、几何、样式全部由 plan 决定；编译前阻断硬错误，不静默改设计。

## 六条硬事实

- **坐标单位是英寸**，原点在页面左上角；16:9 画布 13.333 × 7.5，4:3 是 10 × 7.5；字号单位是 pt。
- **编译器总是生成新文件**，不就地修改原稿；目标文件已存在时默认不动。
- **视觉质量只有在真实渲染且确实看过图像时才可能被判断**。缺任一条件，如实说未核验。
- **核验状态只有三档**：`BLOCK` 有硬问题、`PARTIAL` 对象核对通过但渲染没跑、`READY` 对象与渲染都一致。三档都不表示"设计通过"；`layers.human` 永远是 `NOT REVIEWED`，只有看图的人能改它。
- **`duotone` 在 PowerPoint 生效，LibreOffice 只做去饱和**：渲染核验能证明结构与明暗，不能证明色相。
- **定点编辑有边界**：不新增页、不复制页、不改页序、不改系列数、不动母版与版式本身、不能加动画或切换；组内对象要先取消组合；组合图不给改数。

## v6 → v7

plan 契约只动了一处（`rotation` 允许 ±360，原先 ±180 会把竖排 `270` 判为非法）；`edit.json` 格式不变，v6 的 plan 与改稿指令直接可用。这一版修的是"看起来通过、其实没查"与"改了一处、顺手改坏另一处"。

- **改稿不再压平混排**：`text` 操作原先按第一段样式重写全段，真实稿的 14pt 灰色括注被 32pt 覆盖，而报告仍写"保留核对 READY"。现在逐段取原稿对应段为基线、run 数一致时按位置继承，不一致才回退并记 `W-RUNS`；"只改文字"的闸从"比第一段"改成**逐段样式集合，只禁新增样式**。
- **保留核对从三层补到四层**：新增包内部件逐字节哈希比对（母版主题、备注页被意外重写时，页数、母版、逐页特性、对象指纹全都对得上）。未点名对象改用指纹（填充／描边／裁切／图片哈希／图表结构），不再只看文字。**核对不通过不落交付路径**，原先失败时文件已经写到 `out` 了。
- **旋转三处错**：外接框对 100°–170° 算出负宽（`abs(rotation) % 180` 且没取 cos/sin 绝对值），旋转感知的越界与重叠因此可能漏判；`rotation: 270` 被 schema 拒；编译出口不归一化。三处一起修，新增"竖排 270°"与"旋转后才重叠"两条用例。
- **渲染核对有两条检查长期没响过**：渲染行坐标是 PDF 点（1/72 in）而 plan 是英寸，`V-PUNCT`／`V-ORPHAN` 的归属判断恒不成立；孤字判定又依赖 PDF block，而 LibreOffice 把每行写成独立 block。两条都是全绿用例，靠反向构造才暴露。
- **渲染跳过不再谎报 READY**：缺 LibreOffice 或转换失败时，状态是 `PARTIAL`，报告分层记 `objects` / `render` / `human`。
- **新增四类核验**：预期文字与真实渲染文字逐块比对（`V-TEXT-RENDER`）、声明的角度是否真进渲染（`V-ROT`）、文件结构（`V-PARTS`：slide 部件数、原生图表数、内嵌工作簿数、media 数）、环图逐点直标的数字格式是否丢单位。
- **字体写入不再凭空补**：`set_run_attrs` 曾在只声明西文字体时连 `a:ea` 一起写，既让"只改字"被 `E-PRESERVE` 误报，也改变了目标机的中文回退行为；现在只在显式给出时写。
- **`a:blip` 子元素顺序错**：`duotone` 被 `insert(0)` 到 `alphaModFix` 之前，PowerPoint 对顺序敏感。现在先写透明度再写双色调，并按固定后继表定位插入。
- **装载估算低估混排**：原来只按单一字号算高度，`32pt + 14pt` 的标题会被判成装得下。现在逐段取最大字号、逐 run 折算宽度、计入段后距（`space_after_pt`）。
- **图表两处诚实化**：`value_axis.note`（截轴起点）不再假装画进图里，改由 `W-NOTE` 要求它落到 caption／轴名／图题上；读不到轴开关或轴名时给 `I-AXIS`，不再静默 `pass`——静默跳过与查过无事长得一模一样。改数遇到多图层组合图直接拒绝，不再默默只改柱层。
- **精简**：删掉重复定义的 `_DLBL_ORDER`、`plan.schema.json` 里不存在的 `"table"` 分支、渲染解析里重复的 `get_text` 调用；渲染容差从硬编码收进 `limits.json`。
- **代价要说清**：四份文档 81,202 → 91,643 字节（+12.8%），代码 217,228 → 246,846 字节（+13.6%）。增量集中在 `verify.py`（+13.7KB，五项新核验）与 `revise.py`（+12.1KB，逐段保真、四层核对、按部件名的放行）；`SKILL.md` 只涨 1.4KB——新增的规范写进 `build.md`，主文件保留判断与红线，重复说明按"一处详述、别处只留一句结论或指针"收过（"状态三档""定点编辑四层"都按这个办法）。
- **回归**：负向用例 48 条（v6 是 31 条），每条都是"先破坏、再确认它会响"。七页矩阵、4:3、边界与旋转样张全链路 `READY`；`revise.py` 十五种操作（含改数）保留核对通过，报告注明"声明过的改写 2 个部件"，即那张图自己的 `chart1.xml` 与内嵌工作簿，别的部件一个字节没动。

**未验证的部分**：成稿没有在真实 Microsoft PowerPoint 中打开过，只在 LibreOffice 下渲染；`duotone` 在 LibreOffice 只体现为去饱和；没有做人工视觉评审，所以本包任何地方都不声称"设计通过"。
