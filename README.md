# ppt-visual-art-director

**v5.1.0** — 让 AI 以视觉设计总监的方式做 PPT：新建稿把判断写成 brief、把设计写成 plan、确定性地落成原生可编辑 PPTX；既有稿先解析读懂，再定点编辑，保留原有内容、结构与格式。

它不做模板套用，也不从行业关键词推风格。工作方式是：读懂受众与证据 → 找一条洞察 → 定一个能约束全篇的概念（含它否决了什么）→ 定艺术指导 → 排叙事节奏 → 逐页构成 → 编译 → 看真实渲染 → 定点修正。面对既有稿则反过来：先 `inspect` 读出它是什么，再只改被点名的对象，其余一律不许动。

> 一句话原则：设计判断归你，确定性执行归脚本，审美与签收归人。机器检查不等于好看，预览不等于目标环境通过。

## 结构

```
SKILL.md                  判断原则、判断顺序、brief、任务路线、执行、验收、交付
references/
  design.md               概念与原创性、艺术指导、叙事、视觉系统、构图、版式语法、
                          信息设计、排版、色彩、图像与色域压制、诊断、复核维度
  build.md                plan 语义、坐标、叠放、文本与 runs、图表口径、素材、页码、
                          网格、命令、诊断码、机器边界
scripts/
  compile.py              plan.json → 原生可编辑 PPTX（校验 + 编译 + 整稿设计信号）
  verify.py               plan ↔ PPTX ↔ 真实渲染（对象核对、渲染核对、证据报告）
  revise.py               既有 PPTX 的定点编辑（改字／挪框／换图／改数／调层级／换底色）
  inspect_pptx.py         只读解析既有 PPTX（改稿与评审第一步）
  grid.py                 列数或比例 → 英寸坐标；三分线与黄金位
  plan.schema.json        数据契约（字段形状与类型条件）
  limits.json             技术阈值、默认值、字体别名
requirements.txt
```

## 安装

```bash
python -m venv .venv && . .venv/bin/activate      # Windows：.venv\Scripts\activate
pip install -r requirements.txt
```

Python 3.9+。脚本不联网。真实渲染核验另需 LibreOffice；缺失时 `verify.py` 会跳过渲染并说明哪些判断因此没有依据。

## 新建稿三步

```bash
python scripts/grid.py --span 1:6 --span 8:5      # 先算坐标（也可 --split 5,7 / --guides thirds）
python scripts/compile.py plan.json out.pptx      # 再编译（已有同名文件需 --force）
python scripts/verify.py plan.json out.pptx       # 最后核验（写 render/）
```

plan 的最小骨架见 `references/build.md`「最小骨架」。

## 改既有稿三步

```bash
python scripts/inspect_pptx.py 原稿.pptx           # 读出页数、母版、版式、对象、底色、宏
python scripts/revise.py 原稿.pptx edit.json out.pptx
python scripts/inspect_pptx.py out.pptx            # 核对结果，必要时再渲染看
```

`edit.json` 只描述要改什么，不描述整份稿。改完自动做保留核对：页数、母版、版式、主题字体、宏、逐页动画／切换／备注，以及**未被点名对象**的类型／几何／旋转／文字／底色，任何漂移记 `E-PRESERVE` 阻断。原稿永远不会被覆盖。

## 能做什么

- **判断有落点**：`brief` 里写洞察、概念、**否决项**、艺术指导五参数与母题；`veto` 至少一条——否决不了任何东西的概念没有指导力。
- **原生可编辑**：文本（逐段逐 run 混排，`runs` 可跨段换色换字重，可旋转）、图片（裁切、透明度、`duotone` 压进整稿色域）、形状（圆角半径、描边、旋转、渐变与半透明）、路径（折线、箭头、闭合多边形、锚点连接）、组合、表格、图表。
- **图表**：柱（横／竖／堆叠／百分比）、线、面积（含堆叠）、饼、环、散点、柱＋线组合，直标分柱层／折线层／饼环三套规则，轴线与轴名可控。
- **既有稿定点编辑**：十种操作（改字／挪框／改样式／填色／描边／调层级／换图／改数／删对象／换底色），作用在声明的对象上。母版、版式、动画、切换、SmartArt、备注原样保留，不做整稿重写。
- **空间可算**：等分列、按比例切版心（`--split 5,7`）、三分线与黄金位（`--guides thirds|golden`）——先用比例定骨架，再落具体坐标。
- **整稿信号**：连续同构、标题下细线、无功能英文标签、素材复用、待主张页、满幅图开场——只指出位置，判断归人。
- **确定性**：叠放顺序、页码、几何、样式全部由 plan 决定；编译前阻断硬错误，不静默改设计。

## 五条硬事实

- **坐标单位是英寸**，原点在页面左上角；16:9 画布 13.333 × 7.5，4:3 是 10 × 7.5；字号单位是 pt。`path` 与 `group` 的几何由点集或子元素推出。
- **编译器总是生成新文件**，不就地修改原稿；目标文件已存在时默认不动，输出与报告都不得指向 plan 自己。
- **视觉质量只有在真实渲染且确实看过图像时才可能被判断**。缺任一条件，如实说未核验，不要说"已通过"。
- **`duotone` 在 PowerPoint 生效，LibreOffice 只做去饱和**：渲染核验能证明结构与明暗，不能证明色相。
- **定点编辑有边界**：不新增页、不复制页、不改页序、不改系列数、不动母版与版式本身、不能加动画或切换。越过边界的诉求属于重建，不是编辑。

## 从 v4 到 v5

删掉单句 `visual_concept`，换成结构化的 `brief`（洞察／概念／否决／艺术指导／母题）——判断不再只活在对话里。新增 `duotone`、`corner_in`、`pad_in`、`fonts.number`、跨段 `runs`，修正组合图与饼环直标的分层规则；去掉 `shared_basis` 这个可以绕过口径检查的开关；阻断输出路径覆盖 plan 的数据丢失路径；诊断码与级别对齐（`E-` / `W-` / `I-`）。

## 从 v5.0 到 v5.1

- **补上改稿这一半**：此前只会新建。新增 `revise.py`，十种 op 作用在既有 PPTX 的声明对象上，母版／版式／动画／切换／备注原样保留，并做 `E-PRESERVE` 前后比对；编辑后新增 `W-COVER`（文字压在上层不透明对象上，按字形落点算）与 `W-BOUND`（出画布）两条可读性闸。
- **空间从"等分"扩到"比例"**：`grid.py` 加 `--split`（按比例切版心，含沟槽）与 `--guides`（三分线／黄金位）。design.md 的构图章重写为比例、纵深、重心、边缘、动势五段，纵深给四个可执行手段而非形容词。
- **修一处静默降级**：schema 一直允许文字 `rotation`，但 `add_text` 从不应用，verify 也不查——竖排边注与斜置标签会被悄悄拉平。现已编译生效，`verify.py` 加 HARD `V-STYLE` 核对。
- **修三处"看似在查、其实没查"**（都是先看见渲染不对、再回头查代码才发现的）：
  - 环图逐点直标丢失单位（渲染里是 `47` 而不是 `47%`）——逐点 `dLbl` 存在后不再继承绘图区级数字格式；并且 `DataLabel` 没有 `number_format` 属性，写上去是个静默空转的 Python 属性。现按 `CT_DLbl` 的元素顺序显式写入，`verify.py` 加 HARD 核对。
  - `verify_chart_style` 里有一个提前 `return`，饼环的四项检查（直标位置、类别名开关、环带墨色对比、单位）长期没执行——正向测试全绿是因为它根本没跑。已把这段提成独立函数并在 `return` 前调用。
  - 页码墨色两边都按 `page.background` 判底色，而某一页的底色其实来自一张铺满的色块，于是深底上写出深墨页码。现在编译器与核验器共同调用 `pn_ink()`，按期实际落点选墨。
- **`inspect_pptx.py` 补底色与描边**，并修掉传字符串路径时的崩溃。

计划契约（plan.json）未变，v5.0 的 plan 仍可直接编译。诊断净增一条 `W-CHART`（组合图折线层没开直标，折线的量只能目测），以及两处 HARD 核对位：`V-STYLE`（文字旋转被拉平）、`V-CHART`（环图直标丢单位）。
