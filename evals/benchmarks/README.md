# 独立多项目基准治理

本目录只保存基准治理记录与模板，不把内部同步编写的回归案例冒充独立基准。

## 项目覆盖

正式基准集应覆盖：经营复盘、融资路演、项目立项、产品发布、培训材料、数据报告和既有 PPTX 改稿。每类至少一个真实项目；项目方应提供可合法用于评估的脱敏材料。

## 状态

- `DRAFT`：材料或专家标签不完整，不能用于独立能力结论；
- `FROZEN`：输入、目标环境、候选/基线制品、盲评包及至少两名独立专家标签全部固定并有 SHA-256；
- `EXPOSED_REGRESSION`：实现人员已看过，从此只能作为回归集，不能继续宣称独立泛化证据。

## 冻结流程

1. 在实现人员接触案例前，由项目方准备输入和验收目标；
2. 记录 brief、来源包及目标 PowerPoint/OS/字体；
3. 生成候选稿与固定基线稿；
4. 构建去身份、随机编号的盲评包；
5. 至少两名独立评审者分别提交标签或评分；
6. 固定所有制品和标签 SHA-256；
7. 将 case record 设为 `FROZEN`；
8. 首次向实现人员披露后立即填写 `exposed_to_implementers_at`，后续状态改为 `EXPOSED_REGRESSION`。

## 纪律

- 内部 `evals/cases.yaml` 始终是回归集，不是独立专家标签；
- 合成稿可测工程性能，不能证明真实项目质量；
- 没有两名独立专家标签时不得设为 FROZEN；
- 不因分数低而删除案例或修改基线；
- 目标 PowerPoint 未实测时，该案例不能证明目标环境能力；
- 评审身份和业务材料按项目隐私要求另行保管，仓库只保存允许披露的标识和散列。

字段契约见 `schema/benchmark-case.schema.json`。
