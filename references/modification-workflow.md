# 既有 PPTX 安全改稿工作流

> 目标：修改已有演示文稿，同时保留可编辑性、作者明确关系和全稿一致性。`inspect` 只读事实，不能恢复作者主张或原始设计意图。

## 1. INSPECT｜读取可观察事实

```bash
python scripts/pvad.py inspect existing.pptx --out inspection.json
```

检查页面、对象、文字、几何、显式字体/字号、图表载荷、图片散列和保守工程风险。不得把空间邻近、连线或页序自动解释为因果、层级或时间关系。

## 2. 人工补充最小交接

作者或内容负责人必须明确：

- 修改目标和受众决定；
- 受影响页面及核心主张；
- 必须保留的文字、数据、图表、图片和对象；
- 禁止修改或禁止推断的关系；
- 数据单位、期间、口径和来源；
- 验收条件、目标环境和失败回退。

不能确认时保持未决，不从 PPTX 几何猜意图。

## 3. EDIT｜在可审计表示中修改

优先使用已有 deck JSON 或由作者明确维护的构建代码。任意 `.py` 作者稿默认拒绝执行；只有确认来源后才使用 `--allow-author-code`。不得把 inspect 输出直接冒充 plan 或 deck。

## 4. IMPACT｜计算变更范围

```bash
python scripts/pvad.py impact before-deck.json after-deck.json --out impact.json
```

复核范围至少包括：

- 直接变更页；
- 相邻页；
- 同构图或同根因页面；
- 全稿 Schema 与硬门。

## 5. VERIFY｜局部与全稿双重验证

1. 对直接变更页执行 plan—对象—渲染三方核对；
2. 对相邻页执行叙事增量和节奏复核；
3. 对同类页面执行同根因扩检；
4. 对全稿执行 Schema、guard、编译和回读；
5. 在目标 PowerPoint 中复核字体、断行、图表、裁切、编辑和另存；
6. 内容或素材变化后重新完成合规记录。

## 6. CHANGE SUMMARY｜交付变更摘要

交付记录必须列出：新增、删除、修改页面；保留对象；被替换的来源或素材；验证范围；未解决问题；最终 PPTX SHA-256。内容变更后，旧 evidence 和旧 Release 包立即失效。
