# 诊断、复核与交付

评审既有稿、看图复核、读 `W-*` 信号、写交付回复时读本文。判断框架见 `design.md`，字段与诊断码见 `build.md` `elements.md` `ops.md`。

## 一、诊断

症状是入口，按根因归类，**上游优先**：内容与事实、信息架构一变，下游修改可能全部作废。

| 症状 | 根因 | 处理 | 不要 |
| --- | --- | --- | --- |
| 数字与文字打架；无来源的“权威”数字、占位 Logo | 内容与事实 | 回到口径与来源，标未决；示例写明“示例” | 用强调掩盖缺口；把生成图当证据 |
| 每页都对，整稿不对 | 视觉概念 | 重写洞察与概念，重定锁定项 | 逐页涂抹风格 |
| 图干净，整稿没气质 | 艺术指导 | 重定五参数，统一光与色温 | 换更多图、加滤镜 |
| 图好看但读不懂 | 信息设计 | 换更简单的形式，删到必要节点 | 加图例、箭头、说明 |
| 不知先看什么；每页同一骨架；卡片套卡片、图标阵列代替论证；渐变发光即“科技感” | 构图与层级：没按内容关系选组织，用容器与风格词代替论证 | 明确阅读重点，删不承担关系的容器；先用间距分组；按关系换语法 | 给配角一起加粗加色；同一骨架套所有页 |
| 拥挤，断行难看 | 排版 | 改文案、加宽或拆页，按语义改断点 | 缩字号、压行距、空格硬推 |
| 同页深浅底，前景对不上 | 色彩 | 成套换前景与图表编码，或不切 | 只换底色 |
| 预览正常，目标机发虚 | 渲染环境 | 记录环境，换字或提高素材分辨率，交目标机复核 | 为替代字体改设计 |
| 页题是话题（“市场分析”）；正文重念图表数字；结尾只有“谢谢／Q&A” | 没有主张；图文没分工；没有收束 | 改写成论断（写不出就是未决）；图读数、文字写结论与限定；收在决定或下一步 | 用栏目名占位；让文字替图说话 |

自检顺序：缩略总览像不像同一模板复制；每页能否一句话说出主角；删掉任一装饰后信息是否受损。

## 二、复核维度

逐项给 `PASS／BLOCK／NOT VERIFIED`，每项写**实际依据**（机器事实、看过的 PNG 页码，或仅 plan 声明）；没有依据记 `NOT VERIFIED`。**否决项不可抵消**：语义错误、数据失真、无证因果、关键内容不可读，先修，不被其他维度掩盖。

| 维度 | PASS 需要看到 | 典型 BLOCK | 机器事实来源 |
| --- | --- | --- | --- |
| 1 语义与事实 | 关系、条件、口径、时间、证据真实；假设没被画成因果；标题里的数字用数据回算（86%→45% 是掉了 41 个百分点）并写进 `evidence` | 无证因果、口径混画 | 无 |
| 2 层级与阅读路径 | 主张、重点、限定、来源按预期被读到 | 先看到的不是主张 | `W-MONOTONY` `W-CLAIM` `W-EMPTY`（只报形态） |
| 3 构图与空间 | 主次、重心、留白、分组、节奏服务内容 | 发空或拥挤，重心无回秤 | `V-GEOM` `V-CLIP` `V-OVERFLOW` `E-OVERLAP` `V-BLANK` |
| 4 图形与数据 | 基线、节点、统计编码各有职责且可回算 | 截轴未标，柱子不从零起 | `V-CHART` `E-CHART` `W-CHART` `W-NOTE` `W-PPI` |
| 5 排版 | 断行贴合语义，数字单位同组，实际字体与计划一致 | 数字与单位拆行，末行孤字，替换字体后溢出 | `V-TEXT` `V-TEXT-RENDER` `V-RUNS` `V-FONT` `V-PUNCT` `V-ORPHAN` `W-FIT` `W-SPACE` |
| 6 色彩 | 编码一致可辨，深浅切换后前景成套 | 只靠颜色区分关键状态 | `V-STYLE` `V-CONTRAST` `W-GRAY` `W-CONTRAST` `W-BUSY` `W-CROP` |
| 7 概念与整稿 | 概念追溯到洞察，真正约束了图像、色彩、构图；高潮与停顿可辨 | 换行业仍成立，概念只在字段里 | 无 |
| 8 效率与交付 | 每个元素职责清楚；渲染无错位；环境风险已说明 | 装饰条、重复数字；未渲染却声称已预览 | `V-FORMAT` `V-PARTS` `status` `W-IMG-REUSE` `W-ASSET` `I-OPEN` `E-PRESERVE` |

第 1、7 项机器无法回答，brief 填满不等于概念成立。`PARTIAL` 意味着依赖渲染的第 2、3、5、6 维没有依据，只能写 `NOT VERIFIED`，不能因对象核对通过就记 `PASS`。

## 三、缺陷分级与评审骨架

**分级**：S1 否决 → S2 阻断主线 → S3 质量缺陷 → S4 打磨；按根因修，上游优先。**停止条件**：S1 清零，无未处置的 S2，每页主角一句话说得清，剩余 S3/S4 已披露。**验证等级**：L0 plan 与 schema、L1 PPTX 对象与 OOXML、L2 LibreOffice 渲染、L3 PowerPoint 实机与人工签收；`verify.py` 只到 L2。**模式信号**（`W-MONOTONY` `W-RULE` `W-LABEL` `W-IMG-REUSE` `W-CLAIM` `W-GRAY` `W-SPACE` `W-DOMINANT` `I-OPEN`）只指出该看的位置：成立就改，无事写进交付说明。

**评审骨架**：一句话总评 → 否决项（位置与证据；没有就写“未发现”及查了哪些页）→ 复核维度 → 缺陷按严重度 → 最该改的三处 → 没检查什么。不打总分；原稿数字不“顺手修正”，怀疑有误写进 `open_questions`。

## 四、看图与“不能说”

三层各自成立：**对象核对**（几何、逐 run 文字与样式、图片字节、图表数值、OPC 完整性）、**渲染核对**（越界、字体替换、空白页、文字归属）、**人的判断**（构图、主次、概念；目标 PowerPoint 与字体下是否正常）。`powerpoint` 恒为 `NOT VERIFIED`，`human` 恒为 `NOT REVIEWED`。

看图顺序：缩略总览（锚点、密度、明暗节奏）→ 逐页 PNG（空间、主体、图像、色彩是同一个世界吗）→ **转灰度**、按投影尺寸看层级 → 关键页与相邻页并排。机器事实与设计判断分开写，后者引用页码与可观察依据。

**不能说**：没跑 PowerPoint 说“PowerPoint 下正常”；没渲染说“已预览”“无溢出”；`PARTIAL` 说“核验通过”；没看图说视觉通过；把 `READY` 说成“设计通过”；用替代字体的断行当目标环境结论。改稿保留核对不通过则交付路径一个字节不动（`revise.md`）。

## 五、交付回复（六项，每项简短）

1. **交付物**：文件名、页数、画布、SHA-256；改稿写明动过哪些对象、没保住什么。
2. **设计判断**：洞察、概念（含否决）、编辑取舍、艺术指导、节奏，各一句。
3. **核验**：状态与退出码；对象、渲染、字体各自结果；接受的 `W-*` 及理由；`PARTIAL` 写明原因。
4. **视觉复核**：看了哪些页（含灰度），发现与修正；没做写原因。
5. **待人工确认**：谁、在什么环境、看哪几页。
6. **假设与未决**：示例数据、未清权素材、`open_questions`、剩余 S3/S4。
