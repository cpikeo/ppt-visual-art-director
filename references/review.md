# 诊断、复核与教训

评审既有稿、看图复核、读 `W-*` 信号时读本文。判断框架见 `design.md`，字段与诊断码见 `build.md` `elements.md` `ops.md`。

## 八、诊断

症状是入口，按根因归类，**上游优先**：内容与事实、信息架构一变，下游修改可能全部作废。

| 症状 | 根因 | 处理 | 不要 |
| --- | --- | --- | --- |
| 数字与文字打架 | 内容与事实 | 回到口径与来源，标未决 | 用强调掩盖缺口 |
| 无来源的“权威”数字、占位 Logo | 为显得完整而补造 | 删除或标未决，示例写明“示例” | 把生成图当证据 |
| 每页都对，整稿不对 | 视觉概念 | 重写洞察与概念，重定锁定项 | 逐页涂抹风格 |
| 图干净，整稿没气质 | 艺术指导 | 重定五参数，统一光与色温 | 换更多图、加滤镜 |
| 图好看但读不懂 | 信息设计 | 换更简单的形式，删到必要节点 | 加图例、箭头、说明 |
| 不知先看什么，像模板 | 构图与层级 | 明确阅读重点，删不承担关系的容器 | 给配角一起加粗加色 |
| 拥挤，断行难看 | 排版 | 改文案、加宽或拆页，按语义改断点 | 缩字号、压行距、空格硬推 |
| 同页深浅底，前景对不上 | 色彩 | 成套换前景与图表编码，或不切 | 只换底色 |
| 预览正常，目标机发虚 | 渲染环境 | 记录环境，换字或提高素材分辨率，交目标机复核 | 为替代字体改设计 |
| 每页同一骨架；卡片套卡片、图标阵列代替论证；渐变发光即“科技感” | 没按内容关系选组织，用容器与风格词代替论证 | 按关系换语法；先用间距分组；由受众与证据推出图像与材质 | 同一骨架套所有页；用卡片制造层级 |
| 页题是话题（“市场分析”） | 没有主张 | 改写成论断，写不出就是未决 | 用栏目名占位 |
| 正文重念图表数字 | 图文没分工 | 图承担读数，文字写结论与限定 | 让文字替图说话 |
| 结尾只有“谢谢／Q&A” | 没有收束职责 | 收在决定或下一步 | 用致谢代替结论 |

自检顺序：缩略总览像不像同一模板复制；每页能否一句话说出主角；删掉任一装饰后信息是否受损。

## 九、复核维度

逐项给 `PASS／BLOCK／NOT VERIFIED`，每项写**实际依据**：机器事实、看过的 PNG 页码，或仅 plan 声明。没有依据的记 `NOT VERIFIED`。

| 维度 | PASS 需要看到 | 典型 BLOCK |
| --- | --- | --- |
| 1 语义与事实 | 关系、条件、口径、时间、证据真实；假设没被画成因果 | 无证因果、口径混画 |
| 2 层级与阅读路径 | 主张、重点、限定、来源按预期被读到 | 一眼先看到的不是主张 |
| 3 构图与空间 | 主次、重心、留白、分组、节奏服务内容 | 发空或拥挤，重心无回秤 |
| 4 图形与数据 | 基线、节点、线、统计编码各有职责且可回算 | 截轴未标，柱子不从零起 |
| 5 排版 | 断行贴合语义，数字单位同组，实际字体与计划一致 | 数字与单位拆行，末行孤字，替换字体后溢出 |
| 6 色彩 | 编码一致可辨，深浅切换后前景成套 | 只靠颜色区分关键状态 |
| 7 概念与整稿 | 概念可追溯到洞察，真正约束了图像、色彩、构图；高潮与停顿可辨 | 换行业仍成立，概念只在字段里 |
| 8 效率与交付 | 每个元素职责清楚；渲染无错位；环境风险已说明 | 装饰条、重复数字；未渲染却声称已预览 |

**否决项不可抵消**：语义错误、数据失真、无证因果、关键内容不可读，先修，不能被其他维度或总分掩盖。第 7、8 项机器无法回答，必须看图并写依据。

**机器证据归口**，别跨维引用。`V-TEXT-RENDER` 只证明文字与 plan 一致、渲染没掉字，不证明内容为真。

| 维度 | 机器事实来源 |
| --- | --- |
| 2 | `W-MONOTONY` `W-CLAIM` `W-EMPTY`（报形态，读不读得到主张要看图） |
| 3 | `V-GEOM` `V-CLIP` `V-OVERFLOW` `E-OVERLAP` `V-BLANK` |
| 4 | `V-CHART` `E-CHART` `W-CHART` `W-NOTE` `W-PPI` |
| 5 | `V-TEXT` `V-TEXT-RENDER` `V-RUNS` `V-FONT` `V-PUNCT` `V-ORPHAN` `W-FIT` `W-SPACE` |
| 6 | `V-STYLE` `V-CONTRAST` `W-GRAY` `W-CONTRAST` `W-BUSY` `W-CROP` |
| 8 | `V-FORMAT` `V-PARTS` `status` `W-IMG-REUSE` `W-ASSET` `I-OPEN` `E-PRESERVE` |
| 1、7 | 无。brief 字段填满不等于概念成立，也不等于事实为真 |

`PARTIAL` 意味着依赖渲染的第 2、3、5、6 维没有依据，或声明字体未参与渲染。此时只能写 `NOT VERIFIED`，不能因为对象核对通过就记 `PASS`。

## 十、实战教训

每条来自真实渲染对判断的纠正（LibreOffice，无 PowerPoint 实机）。字号、框高、断点的算术已由 `scaffold.py`（`fit_pt` 按 86% 宽度估大字）与 `W-FIT` 承担，渲染是估宽模型的裁判。

1. **标题里的数字用数据回算**，算法写进 `evidence`：`86%→45%` 是掉了 41 **个百分点**，不是“41%”；机器查不出“约少 1 分钟”其实是 2.3 分钟。
2. **巨型数字先算框再算宽**：框高 ≥ 字号 × 字体行高 × 行距 ÷ 72；带单位要算两段宽度（单位取 0.26–0.4 倍字号）；要共基线就按字号差补偿框底。多段文字按整条行盒推进高度。
3. **中文紧邻数字，渲染器会加间距**，估宽须计入。中文单位紧贴数字（12万），西文单位留一个空格（12 ms）；整稿统一一种。断行按语义，显式 `\n` 断在分句处，不调字距。
4. **版面太空和太满一样没做完**：对照页整块在“标题下沿—页脚上沿”间垂直居中；停顿页标题压顶、正文压底，中段留给图。
5. **主角在灰度下也要有明度差**；**强调色是语义，不是图表默认色**：给图写 `chart.palette`，只有首个数据色饱和，其余收彩度，两两灰度差 ≥ 9.5 L*。
6. **柱与面积从 0 起，折线不平滑**；直标不用 0 撑起堆叠（`number_format: '0"%";;'`）；类别 ≤ 8 的柱/饼 scaffold 默认直标读数；散点主角单独成系列。
7. **图上的小字最先失守**：处置是挪字，不是加遮罩；叠在色块上的字在色块上声明 `overlap_allowed`（只有背景图、蒙版、色块等承载层能声明；`hero`/`subject` 图不与文字相交）。
8. **生成图一次可用靠简报**：主体偏一侧、对侧连续低纹理、单光源、无文字，并写成明度数字。程序合成的替身图证明不了影像质量，构图、光线、材质必须用真实素材与人眼判断。
9. **自己写的稿也会违反自己的规则**：写 plan 时最容易在中文与数字间敲空格；`W-SPACE` 提示后由人决定放行。

## 十一、缺陷分级、验证等级、评审骨架

**缺陷分级**：S1 否决（语义错误、数据失真、无证因果、关键内容不可读）→ S2 阻断主线 → S3 质量缺陷 → S4 打磨；按根因修，上游优先。**停止条件**：S1 清零，无未处置的 S2，每页主角一句话说得清，剩余 S3/S4 已披露。

**验证等级**：L0 plan 与 schema、L1 PPTX 对象与 OOXML、L2 LibreOffice 渲染、L3 PowerPoint 实机与人工签收；`verify.py` 只到 L2。

**模式信号**（`W-MONOTONY` `W-RULE` `W-LABEL` `W-IMG-REUSE` `W-CLAIM` `W-GRAY` `W-SPACE` `W-DOMINANT` `I-OPEN`）只指出该看的位置：成立就改，无事就写进交付说明。

**评审骨架**：一句话总评 → 否决项（位置与证据；没有就写“未发现”及查了哪些页）→ 三种整体判断 → 复核维度（`PASS／BLOCK／NOT VERIFIED` 并注明依据类型）→ 缺陷按严重度 → 最该改的三处 → 没检查什么。不打总分；原稿数字不“顺手修正”，怀疑有误写进 `open_questions`。

## 十二、验收分层、看图顺序与交付回复

三层各自成立，不合并成分数：**对象核对**（几何、逐 run 文字与样式、图片字节、图表数值、OPC 完整性）；**渲染核对**（LibreOffice → PDF → PNG：越界、字体替换、空白页、文字归属）；**人的判断**（构图、主次、概念；目标 PowerPoint 与字体下是否正常）。

`verify.py` 状态：`READY` 0 ｜ `BLOCK` 1 ｜ `PARTIAL` 4（渲染没跑、字体被替换、地区字面无法确认）｜ 输入或契约错误 2。三档都不是质量结论；`powerpoint` 恒为 `NOT VERIFIED`，`human` 恒为 `NOT REVIEWED`。

**看图**：整体性（空间、主体、图像、色彩是同一个世界吗）→ 连续性（缩略总览里锚点、密度、明暗节奏）→ 有效性（**转灰度**、按投影尺寸，层级还清晰吗）。顺序：缩略总览 → 逐页 PNG → 灰度 → 关键页与相邻页并排。机器事实与设计判断分开写，后者引用页码与可观察依据。

**不能说**：没跑 PowerPoint 说“PowerPoint 下正常”；没渲染说“已预览”“无溢出”；`PARTIAL` 说“核验通过”；没看图说视觉通过；把 `READY` 说成“设计通过”；用替代字体的断行当目标环境结论。改稿保留核对不通过则交付路径一个字节不动（`revise.md`）。

### 交付回复

1. **交付物**：文件名、页数、画布、SHA-256；改稿写明动过哪些对象、没保住什么。
2. **设计判断**：洞察、概念（含否决）、编辑取舍、艺术指导、节奏，各一句。
3. **核验**：状态与退出码；对象、渲染、字体各自结果；接受的 `W-*` 及理由；`PARTIAL` 写明原因。
4. **视觉复核**：看了哪些页（含灰度），发现与修正；没做写原因。
5. **待人工确认**：谁、在什么环境、看哪几页。
6. **假设与未决**：示例数据、未清权素材、`open_questions`、剩余 S3/S4。
