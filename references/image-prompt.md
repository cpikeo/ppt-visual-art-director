# 图像艺术指导：从意图到可用素材

在已确定需要图之后读取；先由 `art-direction.md` §5 判断素材职责与真实／原生／生成路线，再确定落位框、画幅和是否叠字。生成图不是事实证据；精确标题、数据和需要编辑的标注放回 PPT 原生层。

## 1. 整稿图像世界

定义足以让素材同族的媒介、色温与色域、主光及环境光逻辑、材质、镜头与空间深度；人物、颗粒和后期仅在影响任务时约定。纪实与原生示意可以混用，但须有清楚分工。多光源并非错误：关键是光向、反射、阴影与环境相互可信，不要机械要求每张图只有一盏灯。可用景深引导注意力，但主体关键结构不可用虚化掩盖。

## 2. 图像简报

每张重要图按最终用途写：**视觉意图**（服务哪个主张）、**主体与景别**（识别结构、机位、占比与朝向）、**最终裁切与文字安静区**、必要的光和材质、可观察的淘汰条件。无叠字时如实写 `none — no overlay`。例如“瓶身的轮廓和接缝可辨、左侧连续暗区留给标题”；“显得高端”不能代替简报。证据图另写可核查的主体与淘汰条件；字段形状和 E012 触发条件见 Schema 与契约。

## 3. 提示词：关键意图与主体优先

先写**用途／核心意图、主体及必须正确的结构**，再按需要组织构图与裁切、景别、材质、光、色彩、媒介和风格。只写会影响本图结果的约束，不要求每个维度都出现；少量针对当前风险的负向排除足够，正向结构比堆“高级、电影感、超清”和长串否定词更有用。模型参数只有在本工具实际支持时才使用，不虚构。

- 差：“高级香水广告、电影感、极致质感。”——主体、落点与光线未知。
- 可执行：“概念产品摄影，主体是一只无标签的矩形厚玻璃瓶，深琥珀液体和深色金属盖结构完整；瓶身位于横幅右侧，左侧留连续暗区给白字。右上柔光使玻璃边缘形成连贯高光，瓶底有接触阴影；色域以炭黑和琥珀为主，无伪文字。”
- 若产品有可核查的真实形状，此概念图不能替代已授权的真实产品图；需要精确外观时先取得真实素材。

## 4. 按职责裁决

| 职责 | 必须解决 | 典型否决 |
| --- | --- | --- |
| 背景 | 落字区连续、明度与纹理可承字；图像不抢主张 | 处处有物、强高光穿字，靠浓遮罩补救 |
| 主体 | 景别与占比对应信息粒度，识别结构和关键轮廓完整 | 主体错误、重复、被裁伤或与标题互抢 |
| 细节／证据 | 指明可观察对象与来源，裁后仍可核查 | 仅为丰富画面；生成图假装证据 |
| 概念／示意 | 未知结构保持抽象，风格或注记使其可识别为示意 | 虚构界面、数据、部件或因果 |

## 5. 真实、示意与生成的边界

具体真实产品、人物、地点或事实证据需要真实素材；不可用生成图冒充。概念图标记 `generated=true` 且不得作证据；有辨识度的生成主体也要考虑肖像、隐私和权利。授权与来源按实际凭据记录，未确认保持 `pending`，记录本身不等于法律意见。

真实照片或截图可能含与证据有关的文字、品牌或水印：核查可用权限和可读性，不为统一视觉而擅自抹除、涂改事实。生成图中的伪文字不能当作真实信息；需要精确标注时用原生层。

## 6. 落位、选图与裁切

落位框 → 最终宽高比 → 主体位置与文字区 → 简报 → 提示词／选片 → 裁切 → 带字整页。一次可复用的真实或生成素材，可以通过不同裁切承担定场与细节；每次都核对裁后识别特征、视线方向、安静区和有效分辨率。`crop_focus` 是确定性裁窗中心，不代表程序认出了主体。源图漂亮但裁后主体残缺或穿字，不合格。

## 7. 三级评审与定向迭代

1. **原图**：内容是否符合简报且未冒充事实；主体结构、透视、接触阴影、反射和材质是否可信，有无伪文字或重复缺陷。
2. **最终裁切**：主体关键部分、方向、空间与文字区是否仍成立；ppi 和裁切损失只作技术提示。
3. **整页及相邻页**：文字与图的主次、字形对比、光色和媒介是否支持主张且同族。E013 的可测对比不等于这三级均通过。

| 症状 | 优先修根因 | 无效做法 |
| --- | --- | --- |
| 图美但页面不成立 | 回到本页主张、主角、落位框与图像职责 | 累加风格形容词 |
| 主体认不出／结构错误 | 补识别特征与景别，必要时换素材路线 | 单纯提高分辨率 |
| 光、反射或材质不可信 | 明确主光及环境关系、接触与材质证据 | 只靠后期调色 |
| 裁后穿字或主体残缺 | 按最终画幅重选，改裁窗或版面 | 指望居中裁切 |
| 跨页像两本杂志 | 回到整稿媒介、光色与材质逻辑 | 独立给每图套滤镜 |

每次针对已观察到的缺陷改变有因果关系的变量；主体准、裁后可用、带字可读且同族时停止。重大缺陷反复出现且没有进展时换路线，不作无目的重试。

## 8. 真实生成执行闭环

需要生成图时：① 检查本会话实际可用工具与输入限制；② 定 §2 简报；③ 写并提交 §3 的真实提示词；④ 保存工具返回的图像；⑤ 核验解码、尺寸与实际 SHA-256；⑥ 在 `assets[image_id]` 登记 `generated=true`、`used_as_evidence=false`、真实来源与权利状态，并在 `image_generation` 记录实际 `tool`、`prompt`、`file`、`status`、`sha256`；`file` 必须与 `image_id` 解析到同一物理文件，声明的 `sha256` 必须等于该文件的真实哈希，**同名不同扩展名不算同一文件**；⑦ 编译本次素材；⑧ 以 §7 的原图、裁切与整页／相邻页三级检查记录结论。提示词不是素材，生成工具成功也不是验收通过。

项目工作区另存可复查记录：生成时间、图片实际尺寸、可取得的模型标识、三级检查与重试原因；未知项如实标未知，不向 Schema 强塞未定义字段。无工具、生成失败或权利未确认时，说明原因与影响，保留真实 `pending`/`failed` 状态；不得用空白占位、旧图或虚构调用记录冒充。记录不作为正式技能包或编译器的隐式网络依赖。
