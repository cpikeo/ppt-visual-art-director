# 编译与交付契约指南

本文件解释如何使用契约，**不再复制一套字段、枚举、默认值或阈值**。设计判断见 `SKILL.md`；机器可执行的权威来源如下。

| 权威来源 | 唯一职责 | 主要消费者 / 验证入口 |
| --- | --- | --- |
| `scripts/plan.schema.json` | plan、页面、元素、图表与素材记录的字段形状、类型、枚举和跨字段条件 | 编译器、交付验证器；`test_machine_examples_validate_against_real_schema` |
| `scripts/policy.json` | 画布、默认字体/图表色、排版与几何阈值、质量门和发布政策 | 编译器、交付验证器；契约与安装测试 |
| `scripts/compile_pptx.py` | 校验、确定性推导、原生 PPTX 编译和诊断 | `ppt-vad`；`dev/tests/test_compile.py` |
| `scripts/verify_delivery.py` | plan↔PPTX 对象核对、真实预览、六道质量门与发布结论 | `ppt-vad-verify`；`dev/tests/test_delivery.py` |
| 项目验收配置（本仓库示例：`dev/acceptance.json`） | 强制门、关键页、抽样、目标环境、人工复核与风险批准 | 交付验证器；配置冲突测试 |

机器可消费的完整示例使用 `dev/tests/fixtures/render_deck.json`，测试会对真实 Schema 校验；不要在文档中另维护一份示意 JSON 充当第二契约。

## 1. THINK → BUILD 的执行闸门

当前契约版本为 **2.0**。除整稿身份与目标外，每页必须交接证据状态、叙事角色、主导焦点和构图理由；未决事项、限制与页面验收要求按实际需要交接。`claim` 留空时必须说明未决原因；证据部分成立时必须保留未决项，不得由程序补写。

进入 BUILD 前会发生以下硬阻断：

- 未知字段、缺失必填项、非法类型/枚举、非有限数值、重复页面或元素身份；
- 越界几何、无效图表载荷、无效素材引用，以及生成图被声明为事实证据；
- 多系列饼/环图、负扇区值或零有效总量、系列与类别长度不一致；
- 明确声明不同单位或不共享统计口径的系列仍要求共轴。

多系列图表的 `shared_basis` 是作者对统计口径的明确声明，不是程序猜测。未声明时给出复核提示，严格交付不会放行；声明与系列单位/口径信息互相矛盾时硬阻断。不同单位不得靠静默换算共轴，需先提供可追踪转换并统一载荷，或分拆/使用表格。

图片通过 `image_id` 引用整稿素材记录。来源、授权、隐私、生成属性与证据用途待确认时是 `NOT VERIFIED`；明确阻断或缺少引用记录时不得交付。素材声明不等于外部法律审计。

## 2. 编译行为与可编辑性

```bash
python scripts/compile_pptx.py plan.json output.pptx --assets assets --strict
# 安装后等价入口：ppt-vad plan.json output.pptx --assets assets --strict
```

- 文本、形状、图片、图表和表格保持原生可编辑；对象名使用 `页面ID.元素ID`，支持 G-SEM 对照。
- 文本同时写入西文与东亚字体属性；字号、颜色、字重、对齐和原文不得被静默更改。
- 图片使用 OOXML 非破坏性等比裁切；素材根目录之外的引用不会被接受。
- 表格两种合法载荷由同一个规范化函数解释；编译器和验证器不得各自推断另一套行列含义。
- 图表保留类别顺序、系列顺序、数值、类型、标题、单位和期间。饼/环逐扇区着色并显示占比；调色板对比不足会披露。未提供调色板时使用 policy 的确定默认色并披露，不退回不明主题色。
- `overlap_allowed` 只能由实际下层承载元素授权；全屏面积不自动等于背景，上层元素不能自行豁免重叠。
- 契约失败在创建 PPTX 前返回。运行期缺图或图表异常可能写出带占位的诊断文件，但返回失败，**该文件不是通过产物**。

`--strict` 将未解决复核提示也视为交付阻断。正式交付应使用严格模式，而不是先普通编译后忽略警告。

## 3. 数值一致性筛查的边界

主张和可见标题分别核对，任一文本正确不能替另一文本免责。表格的两种载荷都进入核对。程序可检查有明确来源的数值、方向、单位数量级、期间及部分派生关系；不能把某个数字碰巧匹配当作整句成立。

程序不能证明同值同指标、因果、共同分母、统计定义或证据真实性。无法建立对应时保留复核，不自动生成事实。配色、构图、焦点、信息密度和叙事质量也不得由这些数值检查折算成审美分。

## 4. 诊断码导航

诊断码由实现和测试锁定，下表只帮助定位，不另建一套处置规则。

| 代码 | 定位 | 代码 | 定位 |
| --- | --- | --- | --- |
| `E001` | Schema、身份、类型、枚举与 THINK 交接 | `E007` | 图表/表格载荷与原生创建失败 |
| `E002` | 几何边界与未授权实质重叠 | `E008` | 主张/标题、系列口径及统计一致性 |
| `E003` | 图片文件不可读或无法置入 | `E009` | 图表换色、默认色或标注风险披露 |
| `E004` | 图表契约或数据缺失 | `E010` | 文本装载估算风险；不自动缩字/改文 |
| `E005` | 字号可读性复核 | `E011` | 素材引用、授权、隐私与证据用途 |
| `E006` | 页面碎片/元素数量复核 |  |  |

## 5. VERIFY 与真实交付物

```bash
python scripts/verify_delivery.py plan.json output.pptx \
  --config acceptance.json --render-dir empty-render-dir --report delivery-report.json
# 安装后等价入口：ppt-vad-verify ...
```

验证器读取本次 PPTX 的 SHA，核对页数、对象身份、几何、文本属性、图层顺序、图片裁切、原生图表/表格载荷；指定空渲染目录时，从该 PPTX 重新生成 PDF 和 PNG。报告包含六道质量门、环境、诊断、抽样总体/种子、风险记录和发布结论。

- `PASS`：该门声明范围内已实际执行并通过；不外推到其他门。
- `NOT VERIFIED`：未执行、环境未配置或证据不足；不等于 PASS。
- `BLOCK — Delivery`：存在硬错误、强制门未通过/未完成、权威冲突或越权风险批准。

结构与契约默认全量。关键、高风险、复杂图表和历史问题页全量复核；其余按项目配置做可复现抽样。发现 MUST FIX 或系统性问题时扩大同类页，必要时全量。抽样比例不是质量证明。

## 6. 从 1.x 迁移

1. 按新 Schema 添加契约版本和逐页 THINK 交接；空主张改为显式未决，不依赖告警后继续。
2. 将素材来源/授权/隐私/生成属性集中到整稿素材记录，并让图片引用该记录。
3. 多系列共轴前确认统计口径；多系列饼/环拆图或改用合适表达。
4. 删除对非法类型、颜色、枚举、几何和 Office 主题默认回退的依赖。
5. 重新以 `--strict` 编译，并对实际 PPTX 运行 G-SEM 与真实渲染；不要仅校验旧 plan 文本。
