# 契约：设计判断与机器执行的边界

写 plan、编译、核验或解读诊断时读取。字段形状和可选项以 Schema 为准，技术阈值与路由以 Policy 为准；本文件解释语义及证据边界，不复制完整字段表。

## 1. 权威与执行链

| 来源 | 职责 |
| --- | --- |
| `SKILL.md` / references | 设计判断、优先级、条件与反例 |
| `scripts/plan.schema.json` | 字段、类型、必填、枚举与跨字段形状 |
| `scripts/policy.json` | 技术默认值、阈值、诊断码→门、复核权限与发布状态 |
| `scripts/compile_pptx.py` | 解析、契约检查、确定性编译、数值筛查和装载估算 |
| `scripts/verify_delivery.py` | plan↔PPTX 对象↔真实渲染、质量门与证据报告 |
| `scripts/inspect_pptx.py` | 只读解析既有 PPTX 的事实与客观线索（改稿／评审用），不判断审美，不写回 |
| `scripts/grid.py` | 把列数、边距、沟槽换算为英寸坐标并标出页码保留区；只做算术 |
| 项目自备验收配置 | 强制门、抽样、目标环境、人工记录与风险批准 |

脚本只从自身目录读取 Schema 和 Policy，不依赖开发目录。Markdown 不另立路由表；未登记诊断码按权威漂移阻断。

## 2. THINK 交接语义

- **整稿**：`audience`、`goal`、`core_claim`、`visual_concept` 描述任务与视觉概念；`rhythm` 可交代跨页节奏。报告将其送 G-DECK，不作机器审美评分。
- **页面**：`role` 是叙事职责；`claim` 是主张。`supported` 须有 `evidence`；`partial` 还须有 `open_questions`；`unsupported` 的 claim 留空；不举证的封面、过渡等可用 `not_applicable`。空 claim 须用 `notes` 或 `open_questions` 说明。页面 `notes` 是**设计备注**，只进入 plan 与复核材料，**不会写入 PPTX 的演讲者备注**；编译器也不生成动画与页面切换。需要演讲稿或动画时须在交付说明中告知并另行处理。`focus_element` 指本页存在的单一主角元素；有意并列或关系跨元素用 `focus_unmapped` 说明。所有页的主次由人看渲染判断。
- **元素**：几何单位为**英寸**（`x/y/w/h`，原点在页面左上角，向下为正），`font_size` 为 pt；元素 `id` 页内唯一，成品对象名为 `<page.id>.<element.id>`。文本式样缺省由 Policy 唯一解析，`runs` 拼接必须与 `content` 一致；`fill_alpha` 只用于有色形状。`background` 建议显式声明；图像角色、素材用途、`crop_focus` 与简报须如实交接。
- **图表**：`unit` 是数量级与量纲；图表与系列的单位、期间等声明不得矛盾。多系列共轴前显式 `shared_basis=true`；所有系列单位须一致或均未声明，不能静默换算。表格可以表达不同口径，已声明的单位须在成品可见。`bar` 是原生竖向簇状柱而非横条；`line` 是相邻类别等距的原生分类轴，不按实际日期自动定位。
- **素材**：记录来源、授权、隐私、生成属性与证据用途；`license_status=cleared` 需要凭据位置。生成图不得作证据；`image_generation` 是真实调用、实际文件及 SHA-256 的登记，不是提示词草稿。提供 `--assets` 时，登记 `file` 必须与 `image_id` 解析到同一物理文件，且声明的 SHA-256 必须等于该文件的实际哈希；同名不同扩展名不能互相顶替。已引用的 `pending`／`failed` 生成素材硬阻断，生成图缺登记或权利待确认不得冒充通过。
- **页码**：`page_numbers` 是整稿级契约，缺省使用 Policy 的位置、格式与起始值；编译器按页序生成保留 ID `_page_number` 的原生对象。整稿禁用或指定省略页必须写任务理由。全出血图角区明暗与底色不同，用页面 `page_number_tone` 如实声明。位置、式样及异常以 Schema/Policy 为准，不在页面手写页码。

## 3. 编译保证与边界

Schema、引用、身份、几何、实质重叠、图表长度／配色、素材登记和确定性声明冲突在写文件前检查；HARD 不可复核或风险批准。文本、形状、图表、表格和图片是可编辑原生对象，名称与 plan 对应；字体、颜色、层序、裁切和单位依声明执行，不自动缩字、换色或补数据。运行期素材或图表失败可能写出带 `.error` 的诊断占位文件，同时返回失败；不得作为交付物。

专用原生图表只有柱、线、饼、环及表格；没有 XY 散点、桑基、自动甘特、决策树或绑定端点的连接器。可组合文字、基本形状及分隔条手工表达关系；这些对象可单独编辑，但点的位置或带宽不与数据绑定，移动节点不会自动移动箭头／线。作者须按数据和日期重新计算、连线并渲染；不能实现或信息不足时用文字／表格。可编辑不等于数据驱动或原生专用图型。

数值一致性、字数装载、字号、图像 ppi／裁切和图表对比是筛查或估算，不证明审美、事实、统计定义或目标环境。`--strict` 把尚未具名处置的 SOFT 视为失败；只有 Policy 指定的码可按 code + location 留具名复核，HARD 和素材待定不得借此豁免。真实渲染测到同一文本框后可替代 E010 估算，但目标字体替换仍需 G-TGT。

## 4. 数据语义筛查

E008 阻断机器能识别的直接冲突，如图表与系列单位/期间声明矛盾、共轴口径未确认，以及点名系列与单一相反方向的明确冲突；E016 表示无法核对，包括单位、期间、指标身份或比较区间不明、同值多源、未确认换算、依赖可加性等假设的派生值。年份、`FY`、季度、半年与月份进入同一期间模型：已知年份不同为冲突；整年与未标年份的季度/月无法对齐时记无法核对，不冒充一致。年度主张与年度类别同样参与核对。数值筛查覆盖 `page.claim` 与标题、正文、图注、页脚等全部可见文本；无单位裸数（如仅写年份）跳过。只有类别标签能识别为同粒度且严格递增的期间／日期时，筛查才把首末类别用作时间变化；折线类型本身不是顺序证据，地区、倒序、混合或未知类别转人工复核。筛查也不验证日期间距的视觉比例。同单位、同数值不证明同指标；系列名称的文本匹配只是弱线索，不证明来源真实性。真实事实矛盾必须改正，不能因为留下复核记录而视为成立。

## 5. 诊断码

| 代码 | 语义 | 级别 |
| --- | --- | --- |
| E001 / E002 | Schema、交接、身份或引用／几何和未授权重叠 | HARD |
| E003 / E004 / E007 | 图片不可读／图表缺失／图表表格载荷或创建失败 | HARD |
| E008 | 数据或口径的直接冲突 | HARD |
| E011 | 素材用途、授权隐私、生成登记及内嵌哈希 | HARD：阻断或哈希不符；SOFT：待确认／缺登记，不可具名豁免 |
| E017 / E018 | 页码对象契约／真实渲染页码检查 | HARD |
| E013 | 文字对比或遮挡；无法还原、未定位字形时披露边界 | HARD / SOFT |
| E016 | 数字或指标身份无法核对 | SOFT |
| E005 / E009 / E010 / E012 | 字号／图表颜色／装载估算／图片简报、ppi 与裁切 | SOFT；E009 也可能为 INFO |
| E006 | 旧版按对象数量提示；保留路由兼容，新版不再生成 | 旧 SOFT |
| E015 | 旧版近似字号／墨色提示；路由保留兼容，新版不再生成 | 旧 INFO |
| E014 | 旧版面积主角提示；路由和旧复核记录保留兼容，新版不再生成 | 旧 SOFT |

哪些 SOFT 可具名复核以 `policy.diagnostics.reviewable_codes` 为准；路由以 `policy.diagnostics.gate_of_code` 为准。复核应有责任人、理由与证据，不能证明审美或事实本身。

E009 的图表对比从**成品图表的实际着色**读取（`c:ser`／`c:dPt` 的 `srgbClr`），不用 plan 的 palette 重算编译逻辑——否则编译器着色出错时，核验器会用同一份实现得出同样的结果。系列或数据点在成品中没有显式着色时，按「未能核对」披露，不改判为通过。

E009 同样适用于退隐项：`highlight_category` 里那些「退到背景里」的柱仍然承载数值，必须可辨。由于对比度是**两色之间**的量，而页面底色逐页声明，退隐色不能是一个固定 HEX——同一枚中性灰在白底够 2.11:1、在米白纸上只剩 1.81:1。因此退隐色由 `chart_deemphasis_ink()` 按当页底色兜底到 `min_contrast` 之上，只移动明度、不动色相与阈值；底色偏离默认白而落色被调整时以 INFO 披露，不占用 SOFT 复核名额。

## 6. VERIFY 与交付状态

- **对象核对**：检查页面、几何、身份、图层、文字式样、图片裁切、图表及表格载荷；生成图片的内嵌字节哈希与登记不符记 E011 HARD，未能核对记 G-COMPLY NOT VERIFIED。素材声明不等于外部法律审计。
- **文字对比**：按实际图层合成可还原的底色、形状和图片，优先使用本次渲染词框；背景无法还原或没有可靠落点时披露不确定性。数值不是完整无障碍审计，也不判断颜色是否好看。
- **真实预览**：LibreOffice 从本次 PPTX 生成 PDF，poppler 提取 PNG、逐页尺寸、文字词框和字体；核对页数、页序、每页尺寸、空白、文本边界、断行及字体嵌入。PDF 文本层未完整命中本页文字时，该页页序不确认，不使用它的词框或像素证据。页序未证实或文本与图表重叠导致检查无法归属时，具体项列入 `limitations` / `not_verified`，G-PRE 记 NOT VERIFIED；请求字体缺失时，本次测量只代表替代字体，目标字体交 G-TGT。证据目录必须为空，避免旧结果混入。
- **页码**：E017 查实际对象、编号、角区、样式与图层；E018 查派生页码框内真实 PDF 词框的存在、重复、位置、文字重叠和页面边缘。角区内不相交的年份、数据等不是页码。PDF 词框存在不等于像素可见：E013 另查页码对比，仍须查看 PNG。
- **人工设计**：`focus_human_required` 列出每一页；G-DECK 根据单页、总览、相邻页和叙事判断主角、层级及设计质量，不由面积排名代替。G-TGT 检查目标 PowerPoint、OS、字体和显示。人工 PASS 需具名、可读本地证据及匹配本次 `pptx_sha256`，但系统不能认证评审者身份。

`PASS` 只涵盖实际执行并通过的范围；`NOT VERIFIED` 不等于通过。HARD、强制门失败或未完成、越权批准均为 `BLOCK — Delivery`。默认强制门包含 `G-STR`、`G-SEM`、`G-PRE`、`G-DECK`、`G-TGT`、`G-COMPLY`：真实渲染与人工验收都不能省，人工门不能以风险批准替代。只有项目显式从 `required_gates` 移除某人工门后，才允许有效风险记录逐项覆盖该门的未验证项；记录须匹配本次 PPTX 哈希、未过期、非笼统且绑定该门真实问题。`[页面.元素]` 使用完整定位符，写一个页面 ID 不能自动覆盖该页多个问题；无定位符的问题须点名报告中的完整描述，缺问题描述不得自动批准。预览通过不等于目标 PowerPoint 或审美通过。

G-DECK 基础验收仍须看每页及整稿；抽样仅安排额外深查：关键、高风险、历史问题、含图表／图像及 open/turn/close 页优先，其余按配置与固定种子抽样。抽样比例不是质量证明。

## 7. 版本与兼容

Schema 为 `4.0`，Policy 为 `2.5`，报告版本 `1.5`；计划形状自 4.0 起未迁移。完整变更历史见包根目录 `CHANGELOG.md`。要点：E006／E014／E015 路由保留兼容但新版不再生成；旧版对应复核记录仍可解析，会作为未匹配记录披露，不能代替人工设计验收；生成素材哈希不符归 E011／G-COMPLY；E009 的反强调色由 `chart_deemphasis_ink()` 按当页底色兜底，BUILD 与 VERIFY 共用同一实现。技术默认值及版本以随包 Policy 为准。
